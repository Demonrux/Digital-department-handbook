# Алгоритмы сортировки

На практике сортируемые значения редко существуют сами по себе. Обычно каждое из них входит в состав **записи** (record), где есть **ключ** (сортируемое значение) и сопутствующие данные. Алгоритм сортировки должен переставлять записи вместе с ключами. Если сопутствующие данные объёмные, сортируют не сами записи, а массив указателей — так перемещений меньше.

Сортировка — одна из фундаментальных задач в изучении алгоритмов. Без неё не обойтись при подготовке отчётов, визуализации объектов по уровням, работе с базами данных. Существует большой выбор алгоритмов, и в них применяются самые разные техники — многие из них были разработаны ещё на заре компьютерной эры.

## Постановка задачи

Имеется последовательность однотипных записей, одно из полей выбрано ключевым. Тип ключа должен поддерживать сравнения (`=`, `>`, `<`, `>=`, `<=`). Требуется преобразовать последовательность в порядок возрастания или убывания ключа.

Различают два типа сортировки. **Внутренняя** — данные в оперативной памяти, важно минимизировать число сравнений и обменов. **Внешняя** — данные на медленном устройстве (диск, лента), важно снизить число обращений к нему. В этой главе — только внутренние сортировки.

## Сортировка вставками

Массив делится на **отсортированную** и **неотсортированную** части. На каждом шаге очередной элемент из неотсортированной части **включается** в отсортированную на нужное место — сдвигом вправо всех элементов, которые больше него.

```text
INSERTION_SORT(A)
1  for j ← 2 to length(A)
2      key ← A[j]
3      i ← j - 1
4      while i > 0 and A[i] > key
5          A[i + 1] ← A[i]
6          i ← i - 1
7      A[i + 1] ← key
```

**Сложность:** `O(n²)` в среднем и худшем случае. Но если массив уже отсортирован, внутренний цикл не выполнится ни разу — `O(n)`. Это делает сортировку вставками хорошим выбором для почти отсортированных данных.

## Сортировка выбором

Массив тоже делится на отсортированную и неотсортированную части. На каждом шаге находим **минимальный** элемент в неотсортированной части и меняем его местами с первым элементом этой части.

```text
EXTRACTION_SORT(A)
1  for i ← n downto 2
2      maxIndex ← 1
3      for j ← 2 to i
4          if A[j] > A[maxIndex] then maxIndex ← j
5      swap(A[i], A[maxIndex])
```

Общее число операций: `n + (n-1) + ... + 1 = n(n-1)/2`. **Сложность:** `O(n²)` в любом случае — даже на отсортированном массиве.

**Идея улучшения — квадратичный выбор.** Если `n` — точный квадрат, делим массив на `√n` групп по `√n` элементов. Находим минимум в каждой группе, потом среди «лидеров». Каждый следующий выбор требует не более `√n - 2` сравнений внутри группы плюс `√n - 1` среди лидеров. Итого `O(n√n)` — существенно лучше, чем `O(n²)`.

## Пузырьковая сортировка

Алгоритм прямого обмена сравнивает пары **соседних** элементов и меняет их местами, если они стоят в неправильном порядке. Проход повторяется, пока массив не упорядочится.

```text
BUBBLESORT(A, n)
1  for i ← n-1 downto 1
2      flag ← false
3      for j ← 1 to i
4          if A[j] > A[j+1] then
5              swap(A[j], A[j+1])
6              flag ← true
7      if not flag then return A
```

**Сложность:** `O(n²)` в среднем и худшем случае. Благодаря флагу `flag` минимальная сложность на отсортированном массиве — `O(n)`.

**Особенность:** лёгкие элементы («пузырьки») поднимаются наверх за один проход, а тяжёлые опускаются медленно. Массив `6 1 2 3 4 5` потребует 5 проходов. **Шейкер-сортировка** решает это, меняя направление проходов: справа налево, потом слева направо.

## Сортировка Шелла

Модификация сортировки вставками. Вместо включения элемента в подмассив **непосредственно предшествующих** элементов его включают в подсписок с шагом `h`: `A[i-h]`, `A[i-2h]`, ... Массив разбивается на `h` серий, каждая сортируется отдельно. Затем `h` уменьшается, и процесс повторяется, пока `h` не станет равным `1`.

Рекомендуемая последовательность шагов: `1, 4, 13, 40, 121, ...` (`hᵢ₊₁ = 3hᵢ + 1`). Начинают с наибольшего `h`, при котором `h ≥ n/9`.

**Сложность:** `O(n^(4/3))` — быстрее, чем `O(n²)`, но медленнее, чем `O(n log n)`. На практике — хороший компромисс между простотой и производительностью.

## Пирамидальная сортировка

**Пирамида** (binary heap) — это массив, который рассматривается как **почти полное бинарное дерево**. Каждый узел соответствует элементу массива. На всех уровнях, кроме последнего, дерево заполнено полностью; последний уровень заполняется слева направо.

Индексы в пирамиде связаны просто:

```text
Parent(i) = ⌊i / 2⌋
Left(i)   = 2i
Right(i)  = 2i + 1
```

На большинстве процессоров `2i` — это побитовый сдвиг влево, `2i+1` — сдвиг плюс установка младшего бита, `⌊i/2⌋` — сдвиг вправо. Поэтому эти операции выполняются очень быстро.

**Свойство пирамиды:** `H[i] ≤ H[2i]` и `H[i] ≤ H[2i+1]` — каждый родитель не больше своих детей. Значит, в корне — минимум.

**Построение пирамиды на том же месте (Флойд).** Нижний слой (`m = n/2 + 1, ..., n`) уже образует пирамиду — у этих элементов нет детей. Затем пирамида расширяется влево: каждый новый элемент **просеивается** (sift) вниз до нужной позиции.

**Сортировка:** `n` раз выталкиваем минимум из корня в конец массива, уменьшая размер пирамиды.

**Сложность:** `O(n log n)` в худшем случае. Heapsort «любит» почти отсортированные массивы — фаза построения пирамиды требует мало перемещений. Среднее число перемещений ≈ `n/2 · log n`.

## Быстрая сортировка

Реализация парадигмы **«разделяй и властвуй»**. Выбирается опорный элемент `x`, массив разделяется на две части: слева — элементы меньше `x`, справа — больше. Затем каждая часть сортируется рекурсивно.

```text
PARTITION(a, L, R, x)
1  i ← L
2  j ← R
3  repeat
4      while a[i] < x do i ← i + 1
5      while a[j] > x do j ← j - 1
6      if i <= j then
7          swap(a[i], a[j])
8          i ← i + 1
9          j ← j - 1
10 until i > j
```

**Сложность:** в среднем `O(n log n)`, в худшем — `O(n²)`. Худший случай — когда опорный элемент оказывается наибольшим или наименьшим: одна часть содержит `n-1` элементов, другая — `1`.

**На практике** quicksort часто оказывается оптимальным: константы в `O(n log n)` малы, сортировка выполняется **без дополнительной памяти**. Хорошо работает даже в средах с виртуальной памятью.

Ожидаемое число обменов ≈ `(n-1)/6`, общее число сравнений ≈ `n log n`.

## Сортировка слиянием

Тоже парадигма «разделяй и властвуй», но с тремя чёткими этапами:

1. **Разделение** — последовательность из `n` элементов делится на две по `n/2`.
2. **Покорение** — обе половины рекурсивно сортируются.
3. **Комбинирование** — две отсортированные половины **сливаются** в одну.

Рекурсия заканчивается, когда длина последовательности становится равной `1` — такая последовательность уже отсортирована.

**Процедура Merge** сливает два отсортированных подмассива за `O(n)`. Она копирует их во вспомогательные массивы `L` и `R`, добавляет в конец **пороговые** элементы (бесконечность) и поочерёдно выбирает меньший из двух.

```text
MERGE_SORT(A, p, r)
1  if p < r
2      q ← ⌊(p + r) / 2⌋
3      MERGE_SORT(A, p, q)
4      MERGE_SORT(A, q + 1, r)
5      MERGE(A, p, q, r)
```

**Сложность:** `O(n log n)` в любом случае — и в лучшем, и в худшем. Это главное преимущество перед quicksort.

**Недостаток:** требует `O(n)` дополнительной памяти для временных массивов. Именно поэтому quicksort на практике часто предпочитают.

## Сортировка подсчётом

Работает **только для целых чисел** из известного диапазона `[0, k]`. Идея: для каждого элемента `x` определить, сколько элементов **меньше** него. По этой информации сразу ставим `x` на нужное место.

```text
COUNTING_SORT(A, B, k)
1  for i ← 0 to k
2      C[i] ← 0
3  for j ← 1 to length(A)
4      C[A[j]] ← C[A[j]] + 1
5  // C[i] — количество элементов, равных i
6  for i ← 1 to k
7      C[i] ← C[i] + C[i - 1]
8  // C[i] — количество элементов, не превышающих i
9  for j ← length(A) downto 1
10     B[C[A[j]]] ← A[j]
11     C[A[j]] ← C[A[j]] - 1
```

Обход `A` **с конца** — чтобы сортировка была **устойчивой**: элементы с одинаковыми ключами сохраняют относительный порядок.

**Сложность:** `O(n + k)`. Если `k` сравнимо с `n`, получается линейное время — лучше не бывает. Но требуется дополнительная память `O(n + k)`, и работает только для целых чисел.

## Сравнение алгоритмов

| Алгоритм | Лучший случай | Средний случай | Худший случай | Память | Устойчив |
| :--- | :--- | :--- | :--- | :--- | :---: |
| **Вставками** | `O(n)` | `O(n²)` | `O(n²)` | `O(1)` | Да |
| **Выбором** | `O(n²)` | `O(n²)` | `O(n²)` | `O(1)` | Нет |
| **Пузырьковая** | `O(n)` | `O(n²)` | `O(n²)` | `O(1)` | Да |
| **Шелла** | `O(n log n)` | зависит от шагов | `O(n^(4/3))` | `O(1)` | Нет |
| **Пирамидальная** | `O(n log n)` | `O(n log n)` | `O(n log n)` | `O(1)` | Нет |
| **Быстрая** | `O(n log n)` | `O(n log n)` | `O(n²)` | `O(log n)` | Нет |
| **Слиянием** | `O(n log n)` | `O(n log n)` | `O(n log n)` | `O(n)` | Да |
| **Подсчётом** | `O(n + k)` | `O(n + k)` | `O(n + k)` | `O(n + k)` | Да |

### Что выбирать

- **Вставками** — для маленьких массивов (до 10–20 элементов) и почти отсортированных данных.
- **Выбором** — когда важно минимизировать число обменов (не сравнений).
- **Пузырьковую** — только для обучения; на практике не используется.
- **Шелла** — простой компромисс, когда нужна скорость выше `O(n²)` без сложной реализации.
- **Пирамидальную** — когда важна гарантия `O(n log n)` **и** экономия памяти.
- **Быструю** — по умолчанию для больших массивов; быстрее всех на практике, но без гарантии в худшем случае.
- **Слиянием** — когда нужна устойчивость или стабильное `O(n log n)`; используется для внешней сортировки.
- **Подсчётом** — для целых чисел из небольшого диапазона.

## Итог

- **Сортировка** — упорядочивание записей по ключу. Бывает внутренняя и внешняя.
- **Вставками** — `O(n²)`, но `O(n)` на почти отсортированных данных.
- **Выбором** — всегда `O(n²)`, но мало обменов.
- **Пузырьковая** — `O(n²)`, только для обучения. Шейкер-сортировка — улучшенная версия.
- **Шелла** — `O(n^(4/3))`, модификация вставками с шагом.
- **Пирамидальная** — `O(n log n)` гарантированно, без дополнительной памяти.
- **Быстрая** — `O(n log n)` в среднем, `O(n²)` в худшем, но быстрее всех на практике.
- **Слиянием** — `O(n log n)` всегда, устойчива, но требует `O(n)` памяти.
- **Подсчётом** — `O(n + k)`, но только для целых из известного диапазона.
