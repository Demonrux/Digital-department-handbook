# Хеш-таблицы

<img width="100%" height="480" alt="image" src="https://github.com/user-attachments/assets/6a941e84-8b66-46b4-8823-a235d04dd44b" />


Для многих приложений достаточно **динамических множеств** с тремя операциями: вставка, поиск, удаление. Пример — таблица символов компилятора, где ключи — произвольные строки-идентификаторы. **Хеш-таблица** — эффективная структура данных для реализации таких словарей. Хотя в худшем случае поиск может занять столько же времени, сколько в связном списке (`O(n)`), на практике хеширование исключительно эффективно: при обоснованных допущениях **среднее время поиска — `O(1)`**.

## Идея хеширования

Термин **hashing** (от англ. *to hash* — крошить, рубить, перемешивать) означает **рассеяние**. Идея проста: вместо того чтобы использовать ключ напрямую как индекс массива, мы **вычисляем индекс** по значению ключа с помощью **хеш-функции** `h(key)`. Это значение называется **хеш-адресом** и используется для поиска в таблице.

Хеш-таблица — обобщение обычного массива. Прямая индексация даёт доступ к любой позиции за `O(1)`, но применима только если размер массива достаточен для **каждого возможного** значения ключа. Когда реально хранящихся ключей **мало** по сравнению с пространством возможных, прямая индексация неэффективна — хеш-таблица решает эту проблему, используя массив, размер которого пропорционален числу **реально хранящихся** ключей.

## Прямая адресация

Простейшая технология, хорошо работающая для **небольших** множеств ключей. Пусть ключи берутся из множества `U = {0, 1, ..., m-1}`, где `m` не слишком велико, и все ключи уникальны.

Для представления динамического множества используем массив `T[0..m-1]` — **таблицу с прямой адресацией**. Ячейка `k` соответствует ключу `k`. Если элемента с ключом `k` нет, `T[k] = NIL`.

```text
DIRECT_ADDRESS_SEARCH(T, k)   return T[k]
DIRECT_ADDRESS_INSERT(T, x)   T[key[x]] ← x
DIRECT_ADDRESS_DELETE(T, x)   T[key[x]] ← NIL
```

Все операции работают за **`O(1)`** — быстрее не бывает. Элементы можно хранить **непосредственно** в ячейках таблицы, экономя память на указателях и даже на самих ключах: если известен индекс объекта, ключ известен автоматически.

**Недостаток очевиден.** Если пространство ключей `U` велико, хранить таблицу размером `|U|` непрактично или вовсе невозможно. А если множество реально хранящихся ключей `K` мало по сравнению с `U`, память расходуется впустую.

## Хеш-таблицы и коллизии

Когда множество `K` хранящихся ключей **гораздо меньше** пространства возможных ключей `U`, хеш-таблица требует существенно меньше памяти — до `Θ(|K|)` — при сохранении среднего времени поиска `O(1)`.

При хешировании элемент с ключом `k` хранится не в ячейке `k`, а в ячейке `h(k)`. Хеш-функция отображает пространство ключей `U` на ячейки таблицы `T[0..m-1]`:

```text
h : U → {0, 1, ..., m-1}
```

Цель — **уменьшить диапазон** индексов: вместо `|U|` значений обойтись всего `m` значениями, снизив требования к памяти.

**Проблема:** два ключа могут хешироваться в одну и ту же ячейку. Такая ситуация называется **коллизией**. Полностью избежать коллизий **невозможно**: поскольку `|U| > m`, по принципу Дирихле как минимум два ключа имеют одинаковое хеш-значение. Хорошая хеш-функция может только **минимизировать** количество коллизий — значит, нужен метод их разрешения.

## Хеш-функции

Качественная хеш-функция удовлетворяет **предположению простого равномерного хеширования**: для каждого ключа равновероятно попадание в любую из `m` ячеек, независимо от хеширования остальных ключей. На практике это условие обычно невозможно проверить — распределение вставляемых ключей неизвестно.

При построении хеш-функции полезно, чтобы она **не коррелировала** с закономерностями в данных. Например, в таблице символов компилятора часто встречаются похожие идентификаторы (`pt` и `pts`) — хорошая хеш-функция должна минимизировать шанс попадания их в одну ячейку.

Для большинства хеш-функций пространство ключей приводится к целым неотрицательным числам. Строку можно рассматривать как число в системе счисления с основанием `d`. Например, `pt` при `p = 112`, `t = 116` — это `112 · 128 + 116 = 14452` в системе с основанием 128.

### Хеширование делением

```text
h(k) = k mod m
```

Ключ отображается в ячейку по остатку от деления на `m`. Быстро — одна операция деления. Но `m` нужно выбирать аккуратно:

- **не степень двойки** — иначе `h(k)` берёт только младшие биты `k`, и результат не зависит от старших;
- **простое число**, достаточно далёкое от степени двойки — даёт хорошие результаты.

Пример: для `n = 2000` строк и желаемой длины цепочки около 3 выбирают `m = 701` — простое, близкое к `2000/3`.

### Хеширование умножением

```text
h(k) = ⌊m · (kA mod 1)⌋,   где 0 < A < 1
```

Сначала ключ умножается на константу `A`, берётся дробная часть, потом умножается на `m` и округляется вниз. Достоинство — **значение `m` перестаёт быть критичным**: можно брать степень двойки.

Кнут рекомендовал `A ≈ (√5 − 1) / 2 ≈ 0.6180339887`.

### Универсальное хеширование

Любая **фиксированная** хеш-функция уязвима: злоумышленник может подобрать ключи, которые все попадут в одну ячейку, и среднее время станет `Θ(n)`. Выход — **случайный выбор** хеш-функции из тщательно отобранного класса в начале работы программы. Это называется **универсальным хешированием**.

Пример класса функций:

```text
h_{a,b}(k) = ((a·k + b) mod p) mod m
```

где `p` — большое простое число, `a ∈ {1, ..., p-1}`, `b ∈ {0, ..., p-1}`. Размер `m` выходного диапазона произволен. Всего в семействе `p(p-1)` функций. Рандомизация гарантирует, что **никакой** выбор данных не даст постоянно плохой производительности — как в quicksort со случайным опорным элементом.

## Методы разрешения коллизий

Есть два принципиально разных подхода: **цепочки** и **открытая адресация**.

### Метод цепочек

Все элементы, хешированные в одну ячейку, объединяются в **связанный список**. Ячейка `j` хранит указатель на заголовок списка элементов с хеш-значением `j`; если таких нет — `NIL`.

- **Вставка:** `O(1)` — новый элемент добавляется в начало списка.
- **Поиск:** пропорционален длине списка. При хорошей хеш-функции средняя длина — `α = n/m`.
- **Удаление:** `O(1)` при использовании двусвязных списков.

Метод прост, эффективен и **не требует**, чтобы `α ≤ 1`. Коэффициент заполнения может быть больше единицы.

### Открытая адресация

Все элементы хранятся **непосредственно** в хеш-таблице: каждая запись содержит либо элемент, либо `NIL`. Никаких списков и указателей — это экономит память и позволяет использовать таблицу большего размера.

При вставке мы **исследуем** (probe) ячейки в определённой последовательности:

```text
⟨h(k, 0), h(k, 1), ..., h(k, m-1)⟩
```

для каждого ключа `k` эта последовательность должна быть **перестановкой** всех ячеек, чтобы при необходимости просмотреть всю таблицу. Коэффициент заполнения `α` не может превышать `1` — таблица может переполниться.

**Вставка** ищет первую пустую ячейку:

```text
HASH_INSERT(T, k)
1  i ← 0
2  repeat
3      j ← h(k, i)
4      if T[j] = NIL then
5          T[j] ← k
6          return j
7      i ← i + 1
8  until i = m
9  error "Хеш-таблица переполнена"
```

**Поиск** исследует ту же последовательность, что и вставка. Если встречается `NIL` — ключа нет.

**Удаление** — сложнее. Нельзя просто поставить `NIL`: это разорвёт цепочку поиска для других ключей, чьи последовательности проходили через эту ячейку. Решение — метка **`DELETED`** вместо `NIL`. Но из-за этого время поиска перестаёт зависеть от коэффициента заполнения. Поэтому при необходимости частых удалений **цепочки предпочтительнее**.

### Виды исследования

**Линейное исследование:**

```text
h(k, i) = (h'(k) + i) mod m
```

Прост в реализации, но возникает **первичная кластеризация**: длинные цепочки занятых ячеек имеют тенденцию удлиняться, что увеличивает среднее время поиска.

**Квадратичное исследование:**

```text
h(k, i) = (h'(k) + c₁·i + c₂·i²) mod m
```

Работает лучше линейного, но требует специального выбора `c₁`, `c₂` и `m`, чтобы исследование охватывало все ячейки. Возникает более мягкая **вторичная кластеризация**: если два ключа имеют одну начальную позицию, у них совпадают и все последующие.

**Двойное хеширование:**

```text
h(k, i) = (h₁(k) + i·h₂(k)) mod m
```

Один из **лучших** методов открытой адресации. Последовательность исследования зависит от ключа **дважды**: и начальная ячейка (`h₁(k)`), и шаг (`h₂(k)`) зависят от ключа. По свойствам близко к «идеальной» схеме равномерного хеширования.

### Сравнение методов

| Метод | Удаление | Память | Кластеризация |
| :--- | :--- | :--- | :--- |
| **Цепочки** | Легко, `O(1)` | Указатели + списки | Нет |
| **Линейное исследование** | Сложно, нужен `DELETED` | Только таблица | Первичная |
| **Квадратичное** | Сложно | Только таблица | Вторичная |
| **Двойное** | Сложно | Только таблица | Минимальная |

**Практические рекомендации:**

- **Частые удаления** → цепочки.
- **Максимум памяти под данные** → открытая адресация (нет указателей).
- **Простота** → линейное исследование.
- **Скорость** → двойное хеширование.

## Итог

- **Хеш-таблица** — эффективная структура для словаря: среднее время операций `O(1)`.
- **Прямая адресация** работает за `O(1)` в худшем случае, но требует памяти под всё пространство ключей.
- **Хеш-функция** отображает ключи в диапазон `[0, m-1]`, экономя память.
- **Коллизии** неизбежны: `|U| > m` → по принципу Дирихле хотя бы два ключа попадут в одну ячейку.
- **Хеширование делением:** `h(k) = k mod m`, где `m` — простое, не близкое к степени двойки.
- **Хеширование умножением:** `h(k) = ⌊m·(kA mod 1)⌋`, константа Кнута `A ≈ 0.618`.
- **Универсальное хеширование** — случайный выбор функции из класса, защита от злоумышленного подбора ключей.
- **Цепочки** — списки в ячейках. Просты, поддерживают удаление, `α` может быть больше 1.
- **Открытая адресация** — элементы в самой таблице. Линейное, квадратичное, двойное исследование.
- **Двойное хеширование** даёт лучшие результаты среди методов открытой адресации.
