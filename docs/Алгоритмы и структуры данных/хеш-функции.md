# Хеш-функции

Для многих приложений достаточно **динамических множеств** с тремя операциями: вставка, поиск, удаление. **Хеш-таблица** — эффективная структура для реализации таких словарей. Ключевой элемент хеш-таблицы — **хеш-функция**, которая отображает ключи в индексы массива.

## Прямая адресация

Простейший подход: массив `T[0..m-1]`, где ячейка `k` соответствует ключу `k`. Если элемента с ключом `k` нет — `T[k] = NIL`.

```text
DIRECT_ADDRESS_SEARCH(T, k)   return T[k]
DIRECT_ADDRESS_INSERT(T, x)   T[key[x]] ← x
DIRECT_ADDRESS_DELETE(T, x)   T[key[x]] ← NIL
```

Все операции — `O(1)`. Но есть **недостаток**: если пространство ключей `U` велико, хранить таблицу размером `|U|` непрактично. А если множество реально хранящихся ключей мало, память расходуется впустую.

## Идея хеширования

Когда реальных ключей `K` **гораздо меньше** пространства возможных `U`, хеш-таблица требует существенно меньше памяти — до `Θ(|K|)` — при сохранении среднего времени `O(1)`.

Хеш-функция отображает пространство ключей `U` на ячейки таблицы `T[0..m-1]`:

```text
h : U → {0, 1, ..., m-1}
```

Цель — уменьшить диапазон индексов: вместо `|U|` значений обойтись `m`.

**Проблема:** два ключа могут хешироваться в одну ячейку. Это **коллизия**. Полностью избежать коллизий **невозможно**: поскольку `|U| > m`, по принципу Дирихле хотя бы два ключа имеют одинаковое хеш-значение. Хорошая хеш-функция может только **минимизировать** коллизии.

## Хеширование делением

```text
h(k) = k mod m
```

Ключ отображается по остатку от деления на `m`. Быстро — одна операция деления. Но `m` нужно выбирать аккуратно:

- **не степень двойки** — иначе `h(k)` берёт только младшие биты `k`, результат не зависит от старших;
- **простое число**, достаточно далёкое от степени двойки — даёт хорошие результаты.

Пример: для `n = 2000` строк и желаемой длины цепочки около 3 выбирают `m = 701` — простое, близкое к `2000/3`.

## Хеширование умножением

```text
h(k) = ⌊m · (kA mod 1)⌋,   где 0 < A < 1
```

Сначала ключ умножается на константу `A`, берётся дробная часть, потом умножается на `m` и округляется вниз. **Достоинство:** значение `m` перестаёт быть критичным — можно брать степень двойки.

Кнут рекомендовал `A ≈ (√5 − 1) / 2 ≈ 0.6180339887`.

## Универсальное хеширование

Любая **фиксированная** хеш-функция уязвима: злоумышленник может подобрать ключи, которые все попадут в одну ячейку, и среднее время станет `Θ(n)`. Выход — **случайный выбор** хеш-функции из тщательно отобранного класса в начале работы программы.

Пример класса:

```text
h_{a,b}(k) = ((a·k + b) mod p) mod m
```

где `p` — большое простое число, `a ∈ {1, ..., p-1}`, `b ∈ {0, ..., p-1}`. Размер `m` произволен. Всего в семействе `p(p-1)` функций.

Рандомизация гарантирует, что **никакой** выбор данных не даст постоянно плохой производительности — как в quicksort со случайным опорным элементом. Вероятность плохого хеширования мала и **одинакова** для любого множества ключей одного размера.

## Итог

- **Прямая адресация** — `O(1)` в худшем случае, но требует памяти под всё пространство ключей.
- **Хеш-функция** отображает ключи в диапазон `[0, m-1]`, экономя память.
- **Коллизии неизбежны** — по принципу Дирихле.
- **Деление:** `h(k) = k mod m`, `m` — простое, не близкое к степени двойки.
- **Умножение:** `h(k) = ⌊m·(kA mod 1)⌋`, константа Кнута `A ≈ 0.618`.
- **Универсальное хеширование** — случайный выбор функции из класса, защита от злоумышленника.
