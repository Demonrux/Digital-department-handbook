# Специальные сортировки

**Специальные сортировки** работают **быстрее** `O(n log n)`, потому что **не сравнивают** элементы напрямую. Вместо этого они используют дополнительную информацию: диапазон значений, разрядность, распределение. Плата — применимы только к определённым типам данных.

## Сортировка подсчётом

Работает для **целых чисел** из известного диапазона `[0, k]`. Идея: для каждого элемента `x` определить, сколько элементов **меньше** него. По этой информации сразу ставим `x` на нужное место.

```text
COUNTING_SORT(A, B, k)
1  for i ← 0 to k do
2      C[i] ← 0
3  for j ← 1 to length(A) do
4      C[A[j]] ← C[A[j]] + 1
5  // C[i] — количество элементов, равных i
6  for i ← 1 to k do
7      C[i] ← C[i] + C[i-1]
8  // C[i] — количество элементов, не превышающих i
9  for j ← length(A) downto 1 do
10     B[C[A[j]]] ← A[j]
11     C[A[j]] ← C[A[j]] - 1
```

Обход `A` **с конца** — чтобы сортировка была **устойчивой**: элементы с одинаковыми ключами сохраняют относительный порядок.

**Сложность:** `O(n + k)`. Если `k` сравнимо с `n`, получается **линейное** время — лучше не бывает. Но требуется дополнительная память `O(n + k)`.

**Устойчива.**

**Когда применять:** целые числа из небольшого диапазона. Например, оценки студентов (0–100), возрасты (0–120), байты (0–255).

## Поразрядная сортировка

Применяется к числам с большим количеством разрядов. Идея: сортируем по **каждому разряду**, начиная с младшего. Каждая такая сортировка — **устойчивая** (обычно подсчётом по одной цифре), поэтому после обработки всех разрядов массив отсортирован.

```text
RADIX_SORT(A, d)
1  for i ← 1 to d do
2      устойчиво отсортировать A по i-й цифре
```

**Пример:** для чисел `170, 45, 75, 90, 802, 24, 2, 66`:
- сортируем по единицам: `170, 90, 802, 2, 24, 45, 75, 66`
- по десяткам: `802, 2, 24, 45, 66, 170, 75, 90`
- по сотням: `2, 24, 45, 66, 75, 90, 170, 802`

**Сложность:** `O(d · (n + k))`, где `d` — число разрядов, `k` — основание системы счисления. Для фиксированного `d` — **линейная**.

**Устойчива.**

**Когда применять:** целые числа, строки фиксированной длины, даты.

## Блочная сортировка

Работает для чисел, **равномерно распределённых** на отрезке `[0, 1)`. Идея: разбить отрезок на `n` **блоков** (корзин), раскидать числа по блокам, отсортировать каждый блок отдельно, потом склеить.

```text
BUCKET_SORT(A)
1  n ← length(A)
2  создать n пустых списков B[0..n-1]
3  for i ← 1 to n do
4      вставить A[i] в B[⌊n·A[i]⌋]
5  for i ← 0 to n-1 do
6      отсортировать B[i] любой сортировкой
7  объединить B[0], B[1], ..., B[n-1] в A
```

**Сложность:** `O(n)` в **среднем** при равномерном распределении. В худшем — `O(n²)`, если все числа попали в один блок.

**Устойчивость зависит** от сортировки внутри блоков.

**Когда применять:** равномерно распределённые вещественные числа.

## Сравнение

| Сортировка | Сложность | Память | Устойчива | Применима к |
| :--- | :--- | :--- | :---: | :--- |
| **Подсчётом** | `O(n + k)` | `O(n + k)` | Да | Целые из `[0, k]` |
| **Поразрядная** | `O(d(n + k))` | `O(n + k)` | Да | Целые, строки |
| **Блочная** | `O(n)` в среднем | `O(n)` | Зависит | Равномерные числа |

### Когда что использовать

- **Подсчётом** — маленький диапазон значений.
- **Поразрядной** — большой диапазон, но мало разрядов.
- **Блочной** — равномерно распределённые вещественные числа.
- Во всех остальных случаях — эффективные сортировки `O(n log n)`.

## Итог

- **Специальные сортировки** не сравнивают элементы — они работают за счёт информации о данных.
- **Подсчётом** — `O(n + k)`, целые из диапазона `[0, k]`.
- **Поразрядная** — `O(d(n + k))`, сортирует по разрядам.
- **Блочная** — `O(n)` в среднем, для равномерно распределённых чисел.
- Все три могут быть **быстрее** `O(n log n)`, но применимы **только к своим данным**.
