## Что такое алгоритм

Слово **«алгоритм»** (algorithm) происходит от имени персидского математика **Абу Абд Аллах Мухаммед ибн Муса аль-Хорезми** (ок. 825 г.). Его учебник по математике «Китаб аль-джебр валь-мукабала» дал миру ещё одно слово — **«алгебра»**.

К 1950 году слово «алгоритм» чаще всего ассоциировалось с **алгоритмом Евклида** — процессом нахождения наибольшего общего делителя двух чисел. Он описан в книге Евклида «Начала» (около 300 г. до н.э.) и до сих пор остаётся классическим примером введения в алгоритмизацию.

Современное значение слова близко к понятиям **рецепт**, **процесс**, **метод**, **процедура**, **программа** — но с важным оттенком: алгоритм должен обладать строгими свойствами.

## Свойства алгоритмов

Алгоритм — не просто набор правил. Он обладает **пятью ключевыми свойствами**.

### 1. Конечность

Алгоритм **всегда завершается** после конечного числа шагов. Шагов может быть сколь угодно много, но их число конечно.

Процедура, у которой есть все свойства алгоритма, **кроме конечности**, называется **методом вычислений**. Например, геометрическое построение «наибольшей общей меры» двух отрезков — это метод вычислений: если длины несоизмеримы, процесс никогда не завершится.

### 2. Определённость

Каждый шаг алгоритма **точно определён**. Действия строго и однозначно заданы для каждого возможного случая.

Метод вычислений, выраженный на языке программирования, называется **программой**.

### 3. Ввод

У алгоритма есть **входные данные** — величины, заданные до начала работы или определяемые динамически во время работы.

Число входных данных может быть **равно нулю**.

### 4. Вывод

У алгоритма есть **выходные данные** — величины, связанные с входными данными.

У алгоритма Евклида одно выходное значение — наибольший общий делитель двух входных.

### 5. Эффективность

Все операции алгоритма должны быть **достаточно простыми**, чтобы их можно было точно выполнить за конечное время.

В алгоритме Евклида используются только:
- деление одного целого положительного числа на другое;
- сравнение с нулём;
- присвоение значения переменной.

Это эффективные операции: целые числа представимы конечным числом знаков, и есть способ деления одного числа на другое.

Но те же операции **неэффективны** для действительных чисел с бесконечными десятичными дробями.

### Сводная таблица

| Свойство | Что означает |
| :--- | :--- |
| **Конечность** | Завершается за конечное число шагов |
| **Определённость** | Каждый шаг однозначен |
| **Ввод** | Есть входные данные (возможно, ноль) |
| **Вывод** | Есть результат |
| **Эффективность** | Операции просты и выполнимы |

## Зачем нужен анализ алгоритмов

На практике нужны не просто алгоритмы, а **хорошие** алгоритмы. Один из критериев качества — **время выполнения**. Другие критерии:

- адаптируемость к разным компьютерам;
- простота;
- изящество.

Часто одну задачу можно решить несколькими алгоритмами. Возникает задача **выбора наилучшего**. Этим занимается **анализ алгоритмов** — область, где для заданного алгоритма определяются его рабочие характеристики, обычно **среднее число операций** `Tn`, где `n` — параметр, характеризующий исходные данные.

> **Анализ алгоритмов vs теория алгоритмов.** Анализ изучает **характеристики** конкретного алгоритма. Теория алгоритмов — совсем другая область: она рассматривает **существование** эффективных алгоритмов для заданных величин.

### Почему это важно

Даже при мощном железе и удобных интерфейсах алгоритмы остаются критичными. Пример — **веб-служба маршрутизации**:

- мощное железо — есть;
- графический интерфейс — есть;
- глобальная сеть — есть;
- но **без алгоритмов** не обойтись: вычисление расстояний, визуализация карт, интерполяция адресов.

Более того, даже приложение, «не требующее алгоритмов на высоком уровне», сильно от них зависит: маршрутизация, компиляторы, интерпретаторы — всё это использует алгоритмы.

**Знание алгоритмов** — одно из отличий умелого программиста от новичка.

## Псевдокод

Программистам часто нужно описание алгоритма **для человека**, а не для компьютера. Такие описания — не программы, но структурированнее обычного текста. Они сочетают естественный язык и конструкции языков программирования. Это **псевдокод**.

### Пример: поиск максимума в массиве

**Задача.** Дан массив `A` из `n` целых чисел. Найти элемент с максимальным значением.

**Псевдокод:**

```text
Input:  массив A из n целых чисел (n > 1)
Output: элемент с максимальным значением

1  currentMax ← A[0]                // выполняется один раз
2  for i ← 1 to n - 1 do            // n - 1 раз
3      if currentMax < A[i] then    // n - 1 раз
4          currentMax ← A[i]        // максимум n - 1 раз
5  return currentMax                // выполняется один раз
```

**Реализация на Java:**

```java
public class ArrayMaxProgram {
    static int arrayMax(int[] A, int n) {
        int currentMax = A[0];
        for (int i = 1; i < n; i++) {
            if (currentMax < A[i]) {
                currentMax = A[i];
            }
        }
        return currentMax;
    }

    public static void main(String[] args) {
        int[] num = { 10, 15, 3, 5, 56, 107, 22, 16, 85 };
        int n = num.length;
        System.out.print("Array: ");
        for (int i = 0; i < n; i++) {
            System.out.print(num[i] + " ");
        }
        System.out.println();
        System.out.println("The maximum element is " + arrayMax(num, n));
    }
}
```

Псевдокод **компактнее** Java-кода, его легче читать и понимать. По нему удобно рассуждать о **правильности** алгоритма, не отвлекаясь на детали синтаксиса.

### Конструкции псевдокода

| Конструкция | Что означает |
| :--- | :--- |
| `←` | Присваивание (аналог `=` в Java) |
| `=` | Сравнение на равенство (аналог `==`) |
| `if ... then ... [else ...]` | Условная конструкция |
| `while ... do ...` | Цикл с предусловием |
| `repeat ... until ...` | Цикл с постусловием |
| `for ... do ...` | Цикл со счётчиком |
| `A[i]` | Индексация массива |
| `object.method(args)` | Вызов метода |
| `return value` | Возврат значения |

> **Правило:** псевдокод пишется **для человека**, а не для компьютера. Он должен выражать основные **идеи**, а не детали реализации. Но не следует упускать важные этапы — баланс между общим и частным вырабатывается практикой.

## Простейшие операции

Экспериментальный анализ времени выполнения полезен, но имеет **три ограничения**:

1. Эксперименты проводятся с **ограниченным набором** исходных данных.
2. Для сравнения двух алгоритмов нужно **одинаковое** аппаратное и программное обеспечение.
3. Нужно **реализовать и выполнить** алгоритм.

Поэтому применяют **аналитический подход**:

1. Записать алгоритм на языке программирования.
2. Перевести в последовательность машинных команд.
3. Определить для каждой команды `i` время `ti`.
4. Определить для каждой команды `i` количество повторов `ni`.
5. Вычислить сумму `ti × ni` — это и будет время выполнения.

Этот подход **точен**, но **очень трудоёмок**: требует знания машинных команд, создаваемых компилятором.

### Упрощение: простейшие операции

Вместо машинных команд считают **простейшие операции высокого уровня**:

- присваивание переменной значения;
- вызов метода;
- арифметическая операция;
- сравнение двух чисел;
- индексация массива;
- переход по ссылке на объект;
- возврат из метода.

**Ключевая идея:** время каждой простейшей операции — постоянная величина. Значит, **число операций пропорционально** действительному времени выполнения.

### Пример: подсчёт операций для `arrayMax`

| Шаг | Операции | Количество |
| :--- | :--- | :--- |
| Инициализация `currentMax` | индексация + присваивание | 2 |
| Инициализация счётчика `i` | присваивание | 1 |
| Проверка `i < n` | сравнение | n раз |
| Тело цикла | 4 или 6 операций | от 4(n-1) до 6(n-1) |
| `return currentMax` | возврат | 1 |

Итог:

- **Минимум:** `2 + 1 + n + 4(n-1) + 1 = 5n`.
- **Максимум:** `2 + 1 + n + 6(n-1) + 1 = 7n - 2`.

**Когда минимум:** если `A[0]` — максимальный элемент, `currentMax` не переприсваивается.

**Когда максимум:** если массив отсортирован по возрастанию, `currentMax` переприсваивается на каждой итерации.

## Анализ средних и худших показателей

Время выполнения зависит от **типа исходных данных**. Возникает вопрос: какое время считать «типичным»?

### Средний случай

Время **усредняется** по всем возможным входным данным с учётом их вероятностного распределения.

**Проблема:** нужно знать **распределение** входного потока. Часто это требует теории вероятностей и высшей математики.

### Худший случай

Время **максимально** по всем входным данным размера `n`.

**Преимущества:**
- не требует теории вероятностей;
- определяет, при каком типе данных алгоритм работает дольше всего;
- если алгоритм хорош в худшем случае — он хорош **при любых данных**.

**Аналогия:** чемпион по бегу тренируется **в гору**. Если он побеждает там — победит и на ровной трассе.

### Соглашение

По умолчанию в анализе алгоритмов указывают **худший показатель**, если не оговорено иное.

Для `arrayMax` худший случай: `t(n) = 7n - 2`.

## Итог

- **Алгоритм** — конечная последовательность точно определённых шагов для решения задачи.
- **Пять свойств:** конечность, определённость, ввод, вывод, эффективность.
- Без **конечности** — это **метод вычислений**, а не алгоритм.
- **Анализ алгоритмов** изучает характеристики конкретного алгоритма: время, память.
- **Псевдокод** — описание алгоритма для человека: сочетание естественного языка и конструкций программирования.
- **Простейшие операции** — присваивание, сравнение, вызов, индексация. Их число **пропорционально** времени выполнения.
- **Средний случай** требует теории вероятностей. **Худший случай** — проще и надёжнее.
- По умолчанию анализируют **худший случай**.
