# Динамическое программирование

**Динамическое программирование** (ДП) — это метод решения задач, в которых одну и ту же подзадачу приходится решать многократно. Вместо того чтобы пересчитывать её каждый раз, мы **запоминаем результат** и используем его повторно. Это превращает экспоненциальные алгоритмы в полиномиальные.

Название «программирование» здесь не имеет отношения к написанию кода — оно историческое, от слова «planning» (планирование). Метод разработал Ричард Беллман в 1950-х годах.

## Когда применять

Динамическое программирование применимо, когда задача обладает **двумя свойствами**.

**Оптимальная подструктура** — оптимальное решение задачи можно собрать из оптимальных решений её подзадач. Если кратчайший путь из `A` в `C` проходит через `B`, то его часть от `A` до `B` — тоже кратчайший путь.

**Перекрывающиеся подзадачи** — одни и те же подзадачи встречаются многократно. Именно это делает запоминание выгодным.

Если подзадачи **не перекрываются**, это не динамическое программирование, а **разделяй и властвуй** — как в сортировке слиянием.

Есть **два подхода** к реализации ДП. **Мемоизация** (top-down) — обычная рекурсия с кэшем: перед вычислением проверяем, не считали ли мы это раньше. **Табуляция** (bottom-up) — итеративное заполнение таблицы от маленьких подзадач к большим.

## Числа Фибоначчи

Классический пример. Наивная рекурсия:

```text
FIB(n)
1  if n ≤ 1 then return n
2  return FIB(n-1) + FIB(n-2)
```

Сложность — **`O(2ⁿ)`**, потому что `FIB(n-2)` вычисляется дважды, `FIB(n-3)` — трижды, и так далее. Уже для `n = 40` это около 200 миллионов вызовов.

**Мемоизация** решает проблему: запоминаем уже вычисленные значения.

```text
FIB_MEMO(n, cache)
1  if n ≤ 1 then return n
2  if cache[n] ≠ NIL then return cache[n]
3  cache[n] ← FIB_MEMO(n-1, cache) + FIB_MEMO(n-2, cache)
4  return cache[n]
```

Сложность — **`O(n)`**. Каждое значение считается один раз.

**Табуляция** идёт снизу вверх и вообще не использует рекурсию:

```text
FIB_TAB(n)
1  if n ≤ 1 then return n
2  a ← 0
3  b ← 1
4  for i ← 2 to n do
5      c ← a + b
6      a ← b
7      b ← c
8  return b
```

Сложность — тоже `O(n)`, но памяти нужно всего `O(1)` вместо `O(n)`. Это типичная оптимизация: если для следующего шага нужны только последние два значения, всю таблицу хранить не надо.

## Задача о рюкзаке

**Постановка.** Есть `n` предметов, у каждого вес `w[i]` и стоимость `v[i]`. Есть рюкзак вместимостью `W`. Нужно выбрать подмножество предметов максимальной стоимости, чтобы их суммарный вес не превышал `W`.

Жадный алгоритм здесь **не работает**: если брать самые дорогие или самые лёгкие предметы, можно упустить лучшее сочетание. Нужно динамическое программирование.

**Идея.** Пусть `dp[i][j]` — максимальная стоимость, которую можно набрать из первых `i` предметов при вместимости `j`. Тогда:

- `dp[0][j] = 0` — нет предметов, стоимость нулевая;
- `dp[i][0] = 0` — нет места, стоимость нулевая;
- если `w[i] > j` — предмет не влезает: `dp[i][j] = dp[i-1][j]`;
- иначе — выбираем максимум из «не брать» и «взять»: `dp[i][j] = max(dp[i-1][j], dp[i-1][j - w[i]] + v[i])`.

**Сложность:** `O(n·W)` по времени и памяти. Пространство можно улучшить до `O(W)`, если хранить только предыдущую строку.

## Наибольшая общая подпоследовательность

**Постановка.** Даны две строки. Найти **наибольшую общую подпоследовательность** (longest common subsequence, LCS) — самую длинную последовательность символов, которая встречается в обеих строках в одном и том же порядке, но не обязательно подряд.

Пример: для `"ABCBDAB"` и `"BDCABA"` LCS — `"BCBA"` или `"BDAB"`, длина 4.

**Идея.** Пусть `dp[i][j]` — длина LCS первых `i` символов первой строки и первых `j` символов второй. Тогда:

- если последние символы совпадают — `dp[i][j] = dp[i-1][j-1] + 1`;
- иначе — `dp[i][j] = max(dp[i-1][j], dp[i][j-1])`.

**Сложность:** `O(m·n)`, где `m` и `n` — длины строк.

LCS применяется в биоинформатике (сравнение последовательностей ДНК), в `diff`-утилитах, в проверке плагиата.

## Размен монет

**Постановка.** Есть монеты разных номиналов. Нужно набрать сумму `S` **минимальным** числом монет.

Пусть `dp[s]` — минимальное число монет для суммы `s`. Тогда:

- `dp[0] = 0`;
- `dp[s] = 1 + min(dp[s - coin])` по всем монетам `coin ≤ s`.

**Сложность:** `O(S · k)`, где `k` — число номиналов.

**Важно:** жадный алгоритм («брать самую крупную монету») работает **не всегда**. Для номиналов `1, 3, 4` и суммы `6` жадный даст `4 + 1 + 1 = 3` монеты, а оптимально — `3 + 3 = 2`. Динамическое программирование находит правильный ответ всегда.

## Реализация на C

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

// ===== Числа Фибоначчи (табуляция) =====
long long fib(int n) {
    if (n <= 1) return n;
    long long a = 0, b = 1;
    for (int i = 2; i <= n; i++) {
        long long c = a + b;
        a = b;
        b = c;
    }
    return b;
}

// ===== Задача о рюкзаке =====
int knapsack(const int weights[], const int values[], int n, int capacity) {
    // dp[j] — максимальная стоимость при вместимости j
    int *dp = calloc((size_t)capacity + 1, sizeof(int));
    if (dp == NULL) return -1;

    for (int i = 0; i < n; i++) {
        // Идём с конца, чтобы не использовать предмет дважды
        for (int j = capacity; j >= weights[i]; j--) {
            int take = dp[j - weights[i]] + values[i];
            if (take > dp[j]) dp[j] = take;
        }
    }

    int result = dp[capacity];
    free(dp);
    return result;
}

// ===== Наибольшая общая подпоследовательность =====
int lcs(const char *a, const char *b) {
    size_t m = strlen(a);
    size_t n = strlen(b);

    // Таблица (m+1) x (n+1)
    int **dp = malloc((m + 1) * sizeof(int *));
    for (size_t i = 0; i <= m; i++) {
        dp[i] = calloc(n + 1, sizeof(int));
    }

    for (size_t i = 1; i <= m; i++) {
        for (size_t j = 1; j <= n; j++) {
            if (a[i - 1] == b[j - 1]) {
                dp[i][j] = dp[i - 1][j - 1] + 1;
            } else {
                dp[i][j] = (dp[i - 1][j] > dp[i][j - 1]) ? dp[i - 1][j] : dp[i][j - 1];
            }
        }
    }

    int result = dp[m][n];

    for (size_t i = 0; i <= m; i++) free(dp[i]);
    free(dp);

    return result;
}

// ===== Размен монет =====
// Возвращает минимальное число монет или -1, если набрать нельзя
int coinChange(const int coins[], int k, int sum) {
    const int INF = sum + 1;

    int *dp = malloc((size_t)(sum + 1) * sizeof(int));
    if (dp == NULL) return -1;

    for (int i = 0; i <= sum; i++) dp[i] = INF;
    dp[0] = 0;

    for (int s = 1; s <= sum; s++) {
        for (int i = 0; i < k; i++) {
            if (coins[i] <= s && dp[s - coins[i]] + 1 < dp[s]) {
                dp[s] = dp[s - coins[i]] + 1;
            }
        }
    }

    int result = (dp[sum] == INF) ? -1 : dp[sum];
    free(dp);
    return result;
}

int main(void) {
    // Фибоначчи
    printf("fib(10) = %lld\n", fib(10));           // 55

    // Рюкзак
    int weights[] = { 2, 3, 4, 5 };
    int values[]  = { 3, 4, 5, 6 };
    printf("Рюкзак: %d\n", knapsack(weights, values, 4, 5));  // 7

    // LCS
    printf("LCS: %d\n", lcs("ABCBDAB", "BDCABA"));  // 4

    // Размен монет
    int coins[] = { 1, 3, 4 };
    printf("Размен 6: %d\n", coinChange(coins, 3, 6));   // 2 (3 + 3)
    printf("Размен 11: %d\n", coinChange(coins, 3, 11)); // 3 (4 + 4 + 3)

    return 0;
}
```

### Что важно в реализациях

**Рюкзак — обход с конца.** Если идти по `j` слева направо, можно случайно использовать один предмет несколько раз. Обратный проход гарантирует, что каждая ячейка обновляется на основе **предыдущей итерации**.

**LCS — таблица размером `(m+1) × (n+1)`.** Лишняя строка и столбец нужны как «нулевые» границы — так не приходится отдельно обрабатывать крайние случаи.

**Размен — `INF = sum + 1`.** Максимальное число монет не превышает `sum` (если минимальный номинал `1`). Значит, `sum + 1` — гарантированная «бесконечность», которая не переполнится.

## Итог

- **Динамическое программирование** применяется, когда есть **оптимальная подструктура** и **перекрывающиеся подзадачи**.
- **Мемоизация** (top-down) — рекурсия с кэшем. **Табуляция** (bottom-up) — итеративное заполнение.
- **Фибоначчи**: наивная рекурсия `O(2ⁿ)`, ДП — `O(n)`, табуляция — `O(1)` памяти.
- **Рюкзак**: `O(n·W)` времени и памяти, с оптимизацией — `O(W)`.
- **LCS**: `O(m·n)`, применяется в биоинформатике и `diff`.
- **Размен монет**: жадный алгоритм работает не всегда, ДП — всегда.
- Главное правило: **запоминать результат** и не считать его повторно.
