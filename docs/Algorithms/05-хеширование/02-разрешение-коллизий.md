# Разрешение коллизий

Коллизии в хеш-таблице **неизбежны**. Значит, нужны методы их разрешения. Есть два принципиально разных подхода: **цепочки** и **открытая адресация**. У каждого свои плюсы и минусы.

## Метод цепочек

Все элементы, хешированные в одну ячейку, объединяются в **связанный список**. Ячейка `j` хранит указатель на заголовок списка; если таких нет — `NIL`.

- **Вставка:** `O(1)` — новый элемент добавляется в начало списка.
- **Поиск:** пропорционален длине списка. При хорошей хеш-функции средняя длина — `α = n/m`.
- **Удаление:** `O(1)` при использовании двусвязных списков.

Метод прост, эффективен и **не требует**, чтобы `α ≤ 1`. Коэффициент заполнения может быть больше единицы.

**Недостаток:** указатели занимают дополнительную память.

## Открытая адресация

Все элементы хранятся **непосредственно** в хеш-таблице: каждая запись содержит либо элемент, либо `NIL`. Никаких списков и указателей — это экономит память.

При вставке мы **исследуем** (probe) ячейки в определённой последовательности:

```text
⟨h(k, 0), h(k, 1), ..., h(k, m-1)⟩
```

для каждого ключа `k` эта последовательность должна быть **перестановкой** всех ячеек, чтобы при необходимости просмотреть всю таблицу. Коэффициент заполнения `α` **не может превышать 1** — таблица может переполниться.

**Вставка** ищет первую пустую ячейку:

```text
HASH_INSERT(T, k)
1  i ← 0
2  repeat
3      j ← h(k, i)
4      if T[j] = NIL then
5          T[j] ← k
6          return j
7      i ← i + 1
8  until i = m
9  error "Хеш-таблица переполнена"
```

**Поиск** исследует ту же последовательность, что и вставка. Если встречается `NIL` — ключа нет.

**Удаление** — сложнее. Нельзя просто поставить `NIL`: это разорвёт цепочку поиска для других ключей. Решение — метка **`DELETED`** вместо `NIL`. Но из-за этого время поиска перестаёт зависеть от коэффициента заполнения. Поэтому при частых удалениях **цепочки предпочтительнее**.

## Виды исследования

**Линейное исследование:**

```text
h(k, i) = (h'(k) + i) mod m
```

Прост в реализации, но возникает **первичная кластеризация**: длинные цепочки занятых ячеек имеют тенденцию удлиняться, что увеличивает среднее время поиска.

**Квадратичное исследование:**

```text
h(k, i) = (h'(k) + c₁·i + c₂·i²) mod m
```

Работает лучше линейного, но требует специального выбора `c₁`, `c₂` и `m`, чтобы исследование охватывало все ячейки. Возникает более мягкая **вторичная кластеризация**: если два ключа имеют одну начальную позицию, у них совпадают и все последующие.

**Двойное хеширование:**

```text
h(k, i) = (h₁(k) + i·h₂(k)) mod m
```

Один из **лучших** методов открытой адресации. Последовательность зависит от ключа **дважды**: и начальная ячейка (`h₁(k)`), и шаг (`h₂(k)`) зависят от ключа. По свойствам близко к «идеальной» схеме равномерного хеширования.

## Сравнение

| Метод | Удаление | Память | Кластеризация |
| :--- | :--- | :--- | :--- |
| **Цепочки** | Легко, `O(1)` | Указатели + списки | Нет |
| **Линейное исследование** | Сложно, нужен `DELETED` | Только таблица | Первичная |
| **Квадратичное** | Сложно | Только таблица | Вторичная |
| **Двойное** | Сложно | Только таблица | Минимальная |

### Практические рекомендации

- **Частые удаления** → цепочки.
- **Максимум памяти под данные** → открытая адресация (нет указателей).
- **Простота** → линейное исследование.
- **Скорость** → двойное хеширование.

---

## Итог

- **Цепочки** — списки в ячейках. Просты, поддерживают удаление, `α` может быть больше 1.
- **Открытая адресация** — элементы в самой таблице. Нет указателей, но `α ≤ 1`.
- **Линейное исследование** — простое, но кластеризуется.
- **Квадратичное** — мягче, но сложнее в настройке.
- **Двойное хеширование** — лучшее среди методов открытой адресации.
- Выбор зависит от задачи: удаления → цепочки, скорость → двойное хеширование.
