# Поиск подстроки

**Поиск** — одна из основополагающих операций в вычислительных задачах. Его цель — найти элементы с ключами, соответствующими заданному ключу поиска. Поиск используется повсеместно: в банковских системах для отслеживания счетов, в авиакомпаниях для учёта мест, в поисковых системах для отыскания документов по ключевым словам. В словаре ключи — это слова, а элементы — связанные с ними записи с определениями и произношением.

## Задача о точном совпадении

Пусть задана строка `P` из `m` символов — **образец** (pattern), и более длинная строка `T` из `n` символов — **текст** (text). Задача о точном совпадении заключается в отыскании всех вхождений образца `P` в тексте `T`.

Например, если `P = aba` и `T = bbabaxababay`, то `P` входит в `T`, начиная с позиций 3, 7 и 9. Два вхождения могут перекрываться — как вхождения в позициях 7 и 9.

Эта задача возникает в широком спектре приложений: в текстовых редакторах, утилитах вроде `grep` в UNIX, поисковых системах (Яндекс, Google), библиотечных каталогах, интернет-браузерах и краулерах, цифровых библиотеках, электронных словарях. В молекулярной биологии существуют сотни баз данных с последовательностями ДНК, РНК и аминокислот, где поиск образцов — базовая операция.

## Наивный метод

Наивный метод — отправная точка для всех обсуждений. Левый конец образца `P` ставится вровень с левым концом текста `T`, и все символы `P` сравниваются с соответствующими символами `T` слева направо. Если встретилось несовпадение или `P` исчерпан — при любом исходе `P` сдвигается на одну позицию вправо, и сравнения возобновляются с левого конца. Процесс продолжается, пока правый конец `P` не зайдёт за правый конец `T`.

```text
Алгоритм NativeMatch(T, P):
  Input:  текст T из n символов, образец P из m символов
  Output: индекс начала подстроки или признак отсутствия

  1  for i ← 0 to n - m do
  2      j ← 0
  3      while (j < m and T[i + j] = P[j]) do
  4          j ← j + 1
  5      if j = m then
  6          return i
  7  return "В тексте T нет образца P"
```

Алгоритм состоит из двух вложенных циклов. Внешний проходит все возможные индексы начала шаблона, внутренний — все символы шаблона. В наихудшем случае для каждого символа `T` выполняется до `m` сравнений. Время выполнения — **`O(nm)`**, что при `n ≈ m` даёт квадратичную сложность.

Первые идеи ускорения заключались в попытках сдвинуть `P` при несовпадении больше чем на один символ, но так, чтобы не пропустить вхождения. Увеличение сдвига экономит сравнения, так как `P` продвигается вдоль `T` быстрее.

## Алгоритм Кнута-Морриса-Пратта

Самый известный алгоритм с линейным временем для задачи точного совпадения предложен **Кнутом, Моррисом и Праттом**. Хотя на практике он часто уступает методу Бойера-Мура, он проще объясняется и даёт основу для алгоритма Ахо-Корасик, который эффективно находит все вхождения любого образца из заданного набора.

Идея в следующем. Предположим, при некотором перемещении `P` по тексту `T` наивный алгоритм обнаружил совпадение первых `i` символов из `P`, а при следующем сравнении — несовпадение. В этом случае наивный алгоритм сдвинет `P` на одну позицию. Но часто можно сдвинуть образец **на большее число позиций**, не пропустив вхождений. Причём это можно определить, зная **только место несовпадения в `P`** — без анализа текста.

Для каждой позиции `i` образца `P` определяется `spi(P)` — длина наибольшего собственного суффикса `P[1..i]`, совпадающего с префиксом `P`. На основе этих значений КМП делает сдвиг больше, чем наивный алгоритм, и не выполняет повторных сравнений уже проверенных символов.

Алгоритм КМП совмещает `P` с `T` и сравнивает символы слева направо, как в наивном методе. Но при несовпадении он использует заранее вычисленные значения `sp` для сдвига. Сдвиг гарантирует, что префикс `P` совпадёт с прилегающей подстрокой `T`, поэтому следующие сравнения начинаются не с начала образца, а с позиции `sp'i + 1`.

**Сложность:** `O(n + m)`. В наихудшем случае алгоритм исследует каждый символ текста и шаблона **всего один раз** — это оптимально для задачи точного поиска.

## Алгоритм Бойера-Мура

Алгоритм Бойера-Мура последовательно передвигает образец `P` по тексту `T`, как наивный, но использует **три идеи**, которых нет в наивном методе:

1. **Сравнение символов справа налево** — от конца образца к началу.
2. **Правило плохого символа** — если символ не совпал, можно сдвинуть `P` так, чтобы крайнее правое вхождение этого символа в `P` выровнялось с найденным символом в `T`. Если такого вхождения нет — сдвинуть `P` за точку несовпадения.
3. **Правило хорошего суффикса** — если часть образца уже совпала, ищем в `P` крайнюю правую копию этого совпавшего суффикса, которая не является суффиксом `P`, и выравниваем её.

Совместный эффект этих идей позволяет методу обычно проверять **меньше чем `m + n`** символов — это **сублинейное** время. В худшем случае (после некоторого улучшения) алгоритм работает за линейное время.

**Сложность:** в среднем — сублинейная, в худшем случае — `O(n)`. На практике — один из самых быстрых алгоритмов поиска подстроки, особенно для естественного текста.

## Алгоритм Рабина-Карпа

Рабин и Карп предложили алгоритм, основанный на **хешировании**. Идея: каждая подстрока длиной `m` интерпретируется как число в системе счисления с основанием `d` (где `d` — размер алфавита). Образец тоже превращается в число. Тогда поиск совпадения сводится к сравнению чисел.

Для эффективного пересчёта используется **правило Горнера** и **скользящее окно**: значение хеша для следующей позиции вычисляется из предыдущего за `O(1)` — удаляем старший символ и добавляем новый младший.

Проблема: числа могут быть огромными. Решение — считать всё **по модулю простого числа `q`**. Тогда:

- если `ts ≢ p (mod q)` — сдвиг точно недопустим, можно пропустить;
- если `ts ≡ p (mod q)` — возможное совпадение, нужна **проверка посимвольно**.

Совпадения по модулю, не являющиеся настоящими, называются **ложными**. Если `q` достаточно велико, ложные совпадения редки.

**Сложность:** предобработка `O(m)`, поиск в худшем случае `O((n-m+1)·m)`, но **в среднем** `O(n + m)` при небольшом числе допустимых сдвигов.

## Сравнение алгоритмов

| Алгоритм | Худший случай | Средний случай | Особенность |
| :--- | :--- | :--- | :--- |
| **Наивный** | `O(nm)` | `O(nm)` | Проще некуда |
| **Кнут-Моррис-Пратт** | `O(n + m)` | `O(n + m)` | Линейный в худшем случае |
| **Бойер-Мур** | `O(nm)` — простой, `O(n)` — с сильным правилом | Сублинейный | Быстрее всех на практике |
| **Рабин-Карп** | `O(nm)` | `O(n + m)` | Основан на хешировании |

**Что выбрать:**

- **Наивный** — для учебных целей и очень коротких строк.
- **КМП** — когда важна гарантия линейного времени и простота реализации.
- **Бойер-Мур** — для поиска в больших текстах, особенно на естественном языке. На практике самый быстрый.
- **Рабин-Карп** — когда нужно искать несколько образцов одновременно или работать с двумерными образцами.

## Итог

- **Задача поиска подстроки** — найти все вхождения образца `P` в тексте `T`.
- **Наивный метод** сравнивает слева направо со сдвигом на 1. Сложность `O(nm)`.
- **КМП** использует префикс-функцию и сдвигает образец больше чем на 1. Сложность `O(n + m)`.
- **Бойер-Мур** сравнивает справа налево и применяет правила плохого символа и хорошего суффикса. На практике самый быстрый, сублинейный.
- **Рабин-Карп** использует хеширование и скользящее окно. Средняя сложность `O(n + m)`, но возможны ложные совпадения.
- Выбор алгоритма зависит от задачи: для больших текстов — Бойер-Мур, для гарантий — КМП, для нескольких образцов — Рабин-Карп.
